# 未尽之托 战斗规格

版本 v0.5。规则与首批数据供程序实现；验证器是离线规则模型，不是游戏引擎。数据见 [首批内容.json](首批内容.json)。

## 1 状态与实体

局内保存 runId、stageId、difficulty、chapter、roster（ID/余额/上限）、wallet、deck（实体 ID/卡定义/升级）、节点与奖励状态。战斗保存 battleId、参战有序 ID、敌人生命、turn/phase/result、预告、五个卡牌区域、个人防护/行动/连击/反击/白饭/保护对象集合与牌库 RNG。

phase 为 between → player → enemy → between，result 为 ongoing/win/loss。已结算战斗不能重开。入场读取账户，筛掉替补专属牌再洗牌，不回复。开局 A×3、D×3、H×2、R×1、基础专属一×2、基础专属二×1，共十二张；GPT 用 G1/G2，Claude 用 C1/C2，DeepSeek 用 S1/S2。

## 2 回合时序

1. 回合加一，清临时防护与保护对象，恢复在线者行动。
2. 按 pattern 预告目标与各段伤害。目标按上场槽位轮换，跳过下线者。群攻必须此时展开到具体目标，不能到结算时补选目标。
3. 抽至五张；不足仅洗弃牌再补，抽弃均空即停，基础动作照常。
4. 验证行动阶段、角色资格、卡牌位置/归属、目标和费用，全部合法才修改任何状态。
5. 加成读操作前状态；支付后执行回复/防护、伤害、状态更新，移动卡并标行动。最后敌人死亡立即 win，停止行动，不再补给。
6. 结束回合时 GPT 跳过断连击。敌方逐段：抵防护 → 扣 token → 下线封存 → 检查全上场失败。离线目标剩余攻击空过，死亡敌人不再行动。
7. 仍 ongoing 时结算 Claude 新反击、DeepSeek 白饭；未用手牌弃置，防护清零。战斗结束不再产出回合末白饭。

## 3 角色与卡牌解释

只有 kind=attack 的卡续 GPT 连击；基础攻击可用 Claude 反击，不续连击、不触发满白饭。攻击附加自护计入 Claude 本回合保护。反击只对一段加 4；G2 满连击额外伤害读取加层前状态。

S2 的 cashRice 优先：基础 8 + 当前层数×2，随后清零，不叠通用满层加成。S1 行动加一层，正常回合末再加一层。这是本版明确新增的快慢选择。

T 目标必须是另一在线者且至少缺 2；先扣使用者 2，再给目标 2，升级额外给目标 2 防护。R 满血使用无收益则拒绝；牌组最多一份，所有获取入口共同检查。升级仅按定义增量一次，不降费用。

所有当前攻击单敌人、单段；无吸血、反伤、死亡攻击或额外行动。多敌人结构可以验证结算边界，不计入首批内容完成数。

## 4 敌人脚本

pattern 按回合循环。难度加压 floor(D/2)，拖延加压 floor((turn−1)/4)，只加到该回合第一段正伤害；全零休整仍为零，多段不能重复叠加。界面显示最终数值。

本次提交版：2 → 1+1 → 4 → 休整。请确认收件人：3 → 2+2 → 5 → 休整。生命在数据文件。第一章按单人，第二章分别测单人跳过招募与双人扩编，临时减少上场人数不缩放敌人。

隐藏模型使用“我”的基础 pattern；非零回合奇数轮应用阶段修正，偶数轮应用一个入场 AI 修正。学生将单段拆成总量不变的两段，员工第一段 +1。GPT 修正为本回合首段受到的攻击减伤 2；Claude 修正为一次尾段 1 伤害；DeepSeek 修正为下回合第一段 +2，当前即公开提示并存储 pending。若下回合为休整，该 pending 顺延至下一有伤害回合。各 AI 候选轮换，优先上场成员，再到替补，候选入场固定。不同时叠多个修正；四个未制作阶段尚无战斗数值。

## 5 节点与奖励

胜利事务包含战斗终态、正余额 +3、算力、固定卡候选、任务片段与下一节点。终章另存普通通关。失败保存失败片段并结束 run，不发胜奖。招募在章底结算后，避免新人重复领 +3。

奖励专属只来自已入队，T 至少两名已入队，R 达上限排除；不足三种显示实际数，可跳过。领取标记与牌组修改一起保存。休息选择互斥；商店验证未用、目标、收益、余额后才扣款回复。总牌组低于八张不可删除，战内封存不受此限。

## 6 存档与收藏

schemaVersion=1；run、战斗与界面流程放入完整快照，任务结果、收藏和恢复作为同一事务。当前实现先生成完整 payload 与 SHA-256 校验封套，写临时文件，重新读取并校验，再替换主档；仅把校验通过的旧主档更新为上一有效备份。主档 JSON、校验值或临时文件损坏时保留并恢复上一有效档；不支持的 schemaVersion 返回明确错误，不静默清空数据。

收藏内容键不含尝试号与修订版本。获得记录可保留首次/最近尝试。相同结算事件不重复增加任何资源；同节点已 win 后收到 loss 必须拒绝。阶段专属替换章底，隐藏另有 battleId/nodeId，与章底分别最多结算一次。

## 7 验收

检查支付原子性、目标锁定、多段/群攻、击杀停手、下线封存、替补回复、0 不复起、R 不循环、T 总量守恒、招募解锁可达、单/双人续战、牌组升级删除、收藏去重与语境、D=T/D>T、普通与专属后隐藏、隐藏失败保存普通成果。实际覆盖与缺口见 [验证报告](验证报告.md)。
