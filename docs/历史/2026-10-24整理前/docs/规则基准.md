### 0.2 裁决原则（明确否认"以文件时间新旧定优先级"）

1. 效力优先于时间：定稿级 > 流程/范围级 > 角色设定级 > 建议级；`_build` 不参与裁决。
2. 定稿级内部冲突时，看**是否被正文重复声明**（总 13.2 与玩 12.1 互相印证的内容视为稳固）；只有一处出现的数值视为**单一来源**，需在本文补记来源。

4. 用户书面意见（改、改2）视为对角色稿的**修订**，但不自动构成新系统。
5. 无法判定时给【建议默认】并登记在决策记录，**不得伪造用户决定**。

## 3. 重点问题逐项处理（K）

> 每条给出：出处 → 问题 → **建议默认方案** → 理由与取舍 → 影响面与可逆性 → 关联裁决。
> 标记【待用户决定】的条目对应决策记录 Q1–Q5，共 5 条，不扩大问题数量。

### K-01 每战回满 token 与休息回血【矛盾】【待用户决定 Q2】

- **出处**：总 4.2、5.1「每场战斗开始时恢复至初始 token」；玩 5.1、5.2 同；玩 5.2「战斗中不自动回满，回复来源为休息节点、卡牌、插件、过载状态」；总 3.2、玩 3.2「休息：恢复 token（兼作回血）；或删卡/升级卡/压缩为摘要卡（二选一）」；总 13.2 将休息节点列为定稿。
- **问题**：若每战开始回满，则**休息回血在数值上恒为无效选项**——玩家在节点里回的血，下一场战斗开始就被重置。休息节点的回血分支成为死选项，且"战斗中回复来源为休息节点"一句在逻辑上不成立（休息发生在战斗外）。
- **建议默认（D-02）**：**保留每战回满**；休息节点**不提供回血**，改为「删卡 / 升级卡 / 压缩为摘要卡 / 角色微调」中选一（原型只做前三项）。凡节点层或身份层的"获取 token"一律解释为**提升初始 token 上限**，不是当场回血。战斗内回复只来自卡牌、插件、过载。
- **理由与取舍**：token 兼生命值的设计意图是"局内决策张力"，不是"跨战运营损耗"。若改战间损耗，需要重做休息、充值、商店、身份订阅费四类节点的经济，并新增回血曲线，属于扩大系统（违反"不能因文档整理扩充系统数量"）。**不变更的核心**：token 仍是共享血量，仍会在一场战斗内被打空而失败。
- **影响面**：总 3.2、13.2；玩 3.2、5.2、12.1、12.2（"回复量"待定项随之解决）；总 10.2 富哥订阅费（见 K-15）。可逆性：**高**（数据与节点选项改动，不改失败判定）。
- **关联**：R-03、R-36、D-02、D-15、Q2。

### K-02 token 归零立即失败与学生救场【矛盾】【待用户决定 Q1】

- **出处**：总 5.1「使用卡牌、受到攻击均消耗 token，归零即失败」；玩 5.2「Token 归零即失败，这是唯一的失败判定」；总 10.2 学生被动「token 为 0 时仍可打出 1 张 0 费卡（每场 1 次）」；玩 5.2「普通卡 0–2，强力卡 3–5（暂定）」；玩 4.2 单人基础 token 为 3。
- **问题**：三处互相打死。
  1. 若"支付导致降为 0"也立即判负，则**玩家永远不能花掉最后一枚 token**；单人基础 3 token 时，任何 3 费强力卡一打出就自杀 → 强力卡实质不可用，与"token 限制爆发频率"的设计目标直接冲突。
  2. 学生被动的"token 为 0 时仍可打 1 张 0 费卡"预设了**归零之后还有一个行动窗口**，与"立即失败"矛盾。
  3. 若"归零判负"只在敌方伤害后检查，则玩家可先花光 token 再让敌人打空——但此时每次受伤都会立即死亡，反而更严酷，需要显式规则。
- **建议默认（D-01）**：把**支付**与**受伤**分开：
  - **主动支付**（出牌、检索/压缩/截断）允许把 token 花到 0；降到 0 时进入**断电状态**：本回合不能再支付任何 token，不能再打出需 token 的卡，只能使用基础行动与 0 费卡。断电不是失败。
  - **受伤/敌方效果**导致 token 降到 0 或以下时，**立即失败**（唯一失败判定，不变）。
  - 学生被动因此自然成立：断电后可额外打 1 张 0 费卡（每场 1 次），这是"救场"而非"免死"——若敌方伤害把 token 打到 0，仍然失败。
- **理由与取舍**：这是让「token 既是费用又是血量」真正可玩的最小改动；不改失败判定本身，只补"判负触发源"。替代方案 B（支付不得使 token 低于 1）会把强力卡变成"永远差 1 费"，且需要扭曲所有卡费；方案 C（任何归零即失败）会让 demo 第一场就无法打出 3 费卡，与玩法 5.2 的费用区间不兼容。**待用户决定**，因为它定义了全游戏最核心的风险感。
- **影响面**：总 5.1、10.2、13.2；玩 5.2、12.1。可逆性：**低**（改的是失败判定语义，牵动所有数值与 UI 提示）。
- **关联**：R-02、D-01、D-16、Q1。

### K-03 手牌容量与上下文负荷（窗口的双重含义）【矛盾】【待用户决定 Q4】

- **出处**：总 1.2「每次使用卡牌增加本回合上下文并消耗 token，**该角色**上下文越满 token 消耗越大，到上限后性能大幅下降；上下文不跨回合保留」；总 5.1「全队共享一个窗口…**本回合窗口占用越高**，后续打出的卡 token 消耗越大；达到上限后角色性能大幅下降」；玩 4.2 窗口容量 5/6/7；玩 5.1 载入"直到窗口达到容量或玩家选择停止"；流「必须先处理的规则问题」明确要求「明确手牌载入容量与本回合已执行的上下文负荷如何关联，用两个数值示例走通；避免开局载满即过载」。
- **问题**：同一句"窗口占用"被用于两件事：①**本回合能载入几张**（容量 5/6/7）；②**本回合已打出几张**（费用递增）。若把"载入即占用"，则回合开始载满 5 张立刻满负荷 → 开局就过载，第一张卡就最贵；若把"打出才占用"，则单人局每回合只打 1 张，递增费用永不触发。此外总 1.2 写"**该角色**上下文"，与"全队共享一个窗口"冲突。
- **建议默认（D-04）**：拆成两个显式数值，二者均**全队共享**：
  - **W＝载入容量**：本回合可载入张数（5/6/7，插件/harness 可修正）；
  - **L＝上下文负荷**：本回合全队**已执行卡牌张数**，回合开始归零（兑现"不跨回合保留"）。
  - **费用** = 卡面费用 + max(0, L − 上场人数)；当 L ≥ W 时，本回合不能再打出卡（窗口已满，兑现"到上限性能大幅下降"），只能基础行动。
  - 载入不增加 L（载入是"准备"，执行才产生负荷）；总 1.2 的"该角色"统一改为"全队"。
- **理由与取舍**：方案 A（本方案）最贴近两文"使用/打出"的措辞，且不改 4.2 的容量数值；代价是**单人固定战斗里 L≤1，递增费用基本不触发**，原型阶段该机制主要由"载入多少张"和"缓存/遗忘"体现压力，递增费用在 2–3 人局才明显。方案 B（载入量直接计入负荷，载入越多本回合越贵）在单人局立刻生效，但会把"载满"变成陷阱，且与总 1.2 的措辞距离更远，需要重新解释 4.2 的 5/6/7。**默认取 A**，B 作为阶段三可切换的实验开关（数据级，可逆）。
- **影响面**：总 1.2、5.1；玩 4.2、5.1、6.1；阶段二战斗规格的整个费用模块。可逆性：**中**（公式可调，但 W/L 双数值的概念应一次定下）。
- **关联**：R-12、R-13、D-04、D-21、Q4。

### K-04 已使用卡的去向（buff 卡 vs 所有卡）【矛盾】

- **出处**：总 6.1「打出的 **buff 卡**进入缓存区」；玩 6.1「**打出的卡**进入缓存区…缓存区有独立上限，可跨回合保留」；玩 5.4 状态「缓存：叠加层数，强化下一次技能」。
- **问题**：只让 buff 卡进缓存，则攻击卡去哪？（被删除了？）让所有卡进缓存，则缓存涨得极快、遗忘频繁，且"缓存叠层"状态会与"缓存卡数"混淆。另：缓存里的卡**能否再次打出**未定义。
- **建议默认（D-05）**：
  - **所有打出的卡**进入缓存区（统一，兑现"会遗忘"主题）；缓存区内的卡**不能再次打出**（缓存是"已执行的上下文"，不是第二手牌）。
  - **强力卡**打出后**直接进入遗忘区**（不进缓存、不可被压缩回收），防止"压缩→回卡组底→再抽到→再打"的循环。
  - 缓存上限【建议】4 张（暂定，插件/harness 可修正）；超限时最旧卡进入**遗忘区**。
- **理由与取舍**：统一的区域规则比"按卡类型分叉"更容易实现、更容易教学，也保住差异化（缓存会满、会遗忘）。强力卡例外是一条**防循环**的针对性规则，代价很小。若用户希望 buff 卡单独叠层，可在阶段四把"缓存叠层"做成状态而非区域。
- **影响面**：总 6.1、7.3；玩 6.1、5.4。可逆性：**高**（区域流向是数据+少量逻辑）。
- **关联**：R-14、R-15、K-07、D-05。

### K-05 未使用卡的去向【空缺】

- **出处**：玩 6.1 只说"载入卡牌进入窗口"，未说回合结束剩牌怎么办；玩 6.1 明确否定传统抽弃循环；总 6.1 亦未定义。
- **问题**：若剩牌留在窗口，则跨回合积累、违背"回合开始归零"；若弃掉，就变成传统弃牌堆（被明令禁止）；若放回卡组**顶**，下回合抽到同样的牌，形成"卡手死循环"。
- **建议默认（D-05）**：回合结束时，窗口内**未打出的自家卡按原顺序放回卡组底**；被敌人塞入的**污染卡**则进入遗忘区（不给玩家"把垃圾还给牌库"的漏洞）。
- **理由与取舍**：回卡组底＝"没用的上下文被退回队列末尾"，既避免卡手循环，又让"这一回合载入几张、留几张"成为真实取舍（留牌＝延后），且不引入新区域、不违反 R-16。
- **影响面**：玩 5.1、6.1；阶段二牌区流转。可逆性：**高**。
- **关联**：K-03、K-06、D-05。

### K-06 牌库耗尽后的玩法【空缺】

- **出处**：两文均未定义；玩 6.1 否定洗牌循环；总 6.1 只说遗忘后"本场战斗内无法使用"。
- **问题**：在"打出即离场、未用回底、超限入遗忘"的规则下，卡组会随战斗变长而变薄，最终可能无牌可载入；此时若无兜底，程序无行为可执行。
- **建议默认（D-06）**：**不自动洗回**。牌库为空时该方"无牌可载入"，只能使用：基础行动、身份主动技能、离线调用（若仍有算力与次数）；玩家可通过卡牌效果把遗忘区/离线区的卡取回（由卡牌文本显式允许）。若阶段三实测出现"空转拖延"，再启用兜底"支付 2 算力把遗忘区洗回卡组底"（列为阶段七调整项，不默认打开）。
- **理由与取舍**：自动洗回会取消"会遗忘"的全部压力（差异化支柱之一）；但完全不兜底可能造成无解僵局，因此保留一个**可开关**的数值级兜底，而不是再写一套循环规则。配套约束：阶段二必须验算"一场战斗在牌库耗尽前能结束"，否则调整敌人伤害或初始卡组张数，而非加系统。
- **影响面**：玩 6.1；阶段二预算。可逆性：**高**。
- **关联**：K-04、K-07、D-06。

### K-07 遗忘与角色离线区的区别【矛盾】

- **出处**：总 6.1「超限时最旧卡被遗忘，本场战斗内无法使用」；玩 6.1「最旧的卡被遗忘：**本场移入离线区或本场移除**」（二义）；总 7.2「专属卡移入"离线区"…角色**复活**后洗回卡组」；玩 7.2「退场时，该角色专属卡从窗口、缓存区移入离线区…角色回归后洗回卡组」（玩 7.2 原文标为"建议规则"）。
- **问题**：玩 6.1 把"遗忘"和"离线区"混为一谈，但离线区的卡会随角色回归回来、还能被离线调用打出，而遗忘的卡应当永久损失——两者混用会让"遗忘"变成免费回收站。另"复活"一词暗示角色会单独倒下，与 R-01/R-02（角色不设 HP、不会单独倒下）冲突。
- **建议默认（D-07）**：设两个互不迁移的区域：
  - **遗忘区（本场移除）**：缓存溢出、截断污染卡、打出强力卡的归宿。本场不可再用，**不随角色回归恢复**，只能由卡牌文本显式取回。
  - **离线区**：只存**退场角色的专属卡**（主动热插拔或强制下线触发，自窗口/缓存移入）。角色回归时洗回卡组；可支付算力离线调用。
  - 术语修订：总 7.2 的"复活"改为"回归"；玩 7.2 的"建议规则"升为本基准 K-07/D-07 的定稿候选，待阶段一验收后写入正式规则。
- **理由与取舍**：这是"遗忘"能否构成真实风险的分水岭。若不拆开，玩家只要让角色下线再上线，就能收回本该遗忘的牌，遗忘机制失效。
- **影响面**：总 6.1、7.2；玩 6.1、7.2；UI 需两个独立区域。可逆性：**中**（区域拆分一旦定下，卡牌文本需同步）。
- **关联**：R-14、R-18、D-07。

### K-08 各种操作的行动预算【空缺】

- **出处**：总 5.2 行动列表只有"使用卡牌、热插拔"，未列基础行动；玩 4.3、5.1 有基础行动（普攻/防御/待机）；总 6.1 的检索/压缩/截断只说"可消耗 token 进行"，未说是否占行动；玩 6.3 离线调用未说是否占行动；总 10.1 身份主动技能"不进卡组、不占上下文与窗口"，未说占不占行动；总 4.2「行动次数 1/2/3」与玩"每名上场角色依次行动一次"并存。
- **问题**：若每个附加操作都占行动，则角色永远打不出卡；若全部免费，则行动经济被附加操作淹没（"无限免费调用"风险）。基础行动是否为"免费永远最优"也未验算。
- **建议默认（D-08）**：采用下表（详见 §6 完整表）。要点：
  - **占行动**：打出卡牌（1 次行动 = 1 张）、基础行动、防御/待机、主动热插拔下线。
  - **不占行动**：载入、调温、检索/压缩/截断（各消耗 1 token、各每回合 1 次）、离线调用（消耗算力、每场每角色 1 次）、身份主动技能（每场限次）。
  - 检索**占用窗口容量**（防无限检索）；压缩只对缓存中的普通卡有效。
  - 单人局中"L 递增费用"不触发，因此附加操作是单人阶段唯一能体验"上下文管理"的手感来源，必须限制次数而非放任。
- **理由与取舍**：最小改动且直接回应"避免永远普攻/无限免费调用"。若把检索/压缩也放进行动，玩家会在"打牌"与"整理窗口"之间被迫二选一，节奏变慢且违背"上下文操作是免费整理手段"的资料印象。
- **影响面**：阶段二/三全部操作实现；玩 5.1 回合流程。可逆性：**中**（次数与是否占行动是数值/开关，可调）。
- **关联**：R-06、R-08、R-09、D-08、D-09。

### K-09 共享 token 下热插拔的效果【矛盾】【待用户决定 Q3】

- **出处**：总 6.3「主动热插拔下线：本回合不行动、**不受伤**，专属卡转为 API 调用模式，下回合回归」；玩 6.3 同；总 13.2/R-01「角色不设独立 HP，受到攻击直接扣全队 token」；玩 4.1「角色退场后不可行动、不可被选为目标」；流「必须先处理的规则问题」：需明确下线免疫的是定向效果、行动封锁还是公共伤害；验证全队下线时敌人如何行动，不能成为无限免伤。
- **问题**：伤害落在**公共 token**上，"某角色不受伤"没有可作用的对象；若解释为"下线角色的存在可以挡掉公共伤害"，则三人全员下线即无限免伤。
- **建议默认（D-03）**：
  1. **公共 token 的伤害不可被热插拔规避**：任何作用于全队的伤害/负面效果，无论谁下线都照常结算。
  2. 热插拔的真实收益只有三条：①该角色**本回合不行动**（主动放弃 1 次行动）；②其专属卡本场失效并移入**离线区**（可被支付算力离线调用）；③免除**只以该角色为目标**的定向效果（单体污染、Skill 封锁、定向减益）——这类效果视该角色不在场，不可选为目标。
  3. **场上必须始终保留至少 1 名在线角色**：下线操作要求当前在线角色 ≥ 2；全员下线不被允许。
  4. 每名角色每场最多主动下线 1 次，且下线后下回合必须回归（避免反复刷单体免疫）。
- **理由与取舍**：这条决定"共享血量"是否还能成立。保留"下线＝放弃行动换战术出口"的设计意图，同时关闭无限免伤与"全员离线"的死结。替代方案（下线角色可额外减免全队 1 点伤害）会把热插拔变成纯收益，不建议。
- **影响面**：总 6.3、13.2；玩 4.1、6.3；敌人 AI 的目标选择逻辑。可逆性：**低**（涉及失败判定与欺骗性 UI 提示）。
- **关联**：R-01、R-25、D-03、Q3。

### K-10 共享窗口下量化如何生效【矛盾】

- **出处**：总 8.2「量化：**缩小队内指定角色的上下文窗口（每回合可载入张数 -1）**，换取全队 token 上限 +1 或费用 -1」；玩 8.2「量化：**缩小该角色的提示词窗口**（每回合可载入张数 -1）…」；R-12/R-20「提示词窗口全队共享一个」。
- **问题**：窗口是全队共享的单一资源，"该角色的窗口 -1"在共享模型下**没有对象**。若直读为"全队窗口 -1"，则量化代价作用全队、收益也作用全队，与"对该角色进行强化"的描述不符，且三人局 -1 过重。
- **建议默认（D-10）**：把"窗口"换成**该角色的上下文负荷门槛**：量化使该角色的**免附加费额度从 2 降为 1**（即该角色打出的第 2 张卡起就开始 +1 费，见 K-03 的 L 公式），换取**全队 token 上限 +1** 或 **该角色专属卡费用 -1**。
- **理由**：量化＝压缩模型＝"上下文变窄、单位运算更快"，用 L 曲线表达正好；且作用在角色级，不影响全队窗口容量，与 R-12 不冲突。备选（若用户偏好"直读"）：量化改为全队 W−1，收益改为"全队 token 上限 +2"以补偿，但会与"跳过招募收益略高于招募"的平衡目标打架。默认取前者，属**可逆**（数值+文本）。
- **影响面**：总 8.2；玩 8.2；阶段五仅实现一种跳过强化。可逆性：**高**。
- **关联**：K-03、D-04、D-10。

### K-12 角色核心 Skill 与插件、harness 的边界【空缺】

- **出处**：总 4.3「每人初始 1 个 skill、1 个插件；各角色插件槽数量不同」；总 1.1「全队共享 token、skill」；总 6.4「Skill…对全队生效」；玩 4.3「角色 Skill…进入全队共享 skill 栏」；总 4.4/玩 4.4 harness「不进卡组、不占窗口…与 Skill、插件、身份不叠加同一乘区」；总 4.4「专属 harness 除属性加成外，额外解锁一条强力被动词条…该词条与本角色 Skill 不重复触发」；角色稿「每人 3–5 条专属机制」（审 165–178 亦已指出冲突）。
- **问题**：角色稿给每人 3–5 条专属机制，而规则只容许 1 条核心 Skill；谁进 Skill、谁进插件、谁进 harness、谁进卡牌，没有任何边界；四层都能"提供被动"，叠加后极易出现数值爆炸与职责重复。
- **建议默认（D-12）**：采用**四层归属 + 三条铁律**（§4 完整表）：
  - **层级归属**：核心 Skill＝每人 1 条、全队生效、被动/触发；插件＝单角色、占槽、数值/条件修正；harness＝单角色 1 槽、装备型属性+1 条词条；身份＝玩家层、全队/玩家效果。

  - **铁律 2（不跨乘区）**：同一属性只允许一个修正源；加算先于乘算；身份/插件/harness 之间不连乘。
  - **铁律 3（3–5 条机制的分摊）**：核心 Skill 1 条 + 卡牌 2–3 条 + 插件 0–1 条 + 微调 0–1 条 + harness 0–1 条，**不得全部做成常驻被动**。
- **理由与取舍**：这是"系统不再膨胀"的关键阀门；也直接回应审阅稿"三到五条专属机制不能全变成常驻被动"。代价是角色稿需要逐条裁剪（审计表见 `docs/决策记录.md` 附件说明）。
- **影响面**：总 4.3、4.4、6.4；玩 4.3、4.4、9；全部角色稿。可逆性：**中**（角色级调整，可逐个改）。

### 4.2 三条铁律（写入阶段二规格，作为数据校验规则）

1. **唯一来源**：同一机制只允许登记在 Skill / 插件 / harness / 身份 四层中的一层；专属 harness 词条与本角色 Skill 不得是同一效果（玩 4.4 已要求"不重复触发"，本文升级为"不得同源"）。

3. **3–5 条机制的分摊**：角色稿给每人的 3–5 条专属机制，必须拆为「核心 Skill 1 + 卡牌 2–3 + 插件 0–1 + 微调 0–1 + harness 0–1」；不得全部做成常驻被动。

### 5.3 判定顺序（阶段二必须照此实现）

1. 回合开始：窗口占用归零 → 结算"回合初触发"（过载回复等）→ 调整温度 → 载入卡牌。
2. 行动阶段：按速度排序，逐名在线角色行动一次；每次支付后立即检查费用是否合法（token 可到 0，进入断电）。
3. 每次 token 因**受伤**下降后立即检查失败（≤0 即失败）。
4. 结算敌人行动 → 回合结束：缓存溢出 → 窗口残留处理 → 结算持续状态。

## 6. 行动与操作预算表

| 操作 | 执行者 | 是否占用角色行动 | 资源成本 | 次数上限 | 可用时点 | 出处 |
| --- | --- | --- | --- | --- | --- | --- |
| 载入卡牌 | 全队（每回合一次） | 否 | 0 | 每回合 1 次，至多 W 张 | 回合开始 | 玩 5.1 |
| 调整温度 | 全队 | 否 | 0 | 每回合 1 次 | 回合开始 | 总 6.2 |
| 打出卡牌 | 该在线角色 | **是**（1 次 = 1 张） | 卡面 token + L 附加 | 每角色每回合 1 次 | 该角色行动时 | 总 4.2；玩 4.2 |
| 基础行动（普攻/特技） | 该在线角色 | **是** | 0 | 每角色每回合 1 次 | 同上 | 玩 4.3、5.1 |
| 防御 / 待机 | 该在线角色 | **是** | 0 | 每角色每回合 1 次 | 同上 | 玩 5.1 |
| 检索 | 全队 | 否 | 1 token（断电不可用） | 每回合 1 次 | 行动阶段 | 总 6.1 |
| 压缩 | 全队 | 否 | 1 token | 每回合 1 次（仅普通卡） | 行动阶段 | 总 6.1 |
| 截断 | 全队 | 否 | 1 token | 每回合 1 次 | 行动阶段 | 总 6.1 |
| 离线调用 | 离线角色 | **否** | 算力（建议 3） | 每场每角色 1 次 | 行动阶段 | 玩 6.3 |
| 主动热插拔下线 | 该在线角色 | **是**（放弃行动） | 0 | 每角色每场 1 次；场上须保留 ≥1 在线 | 该角色行动时 | 总 6.3 + D-03 |
| 身份主动技能 | 玩家 | 否 | 无 token 成本 | 见身份表（每场 1–2 次） | 任意时点 | 总 10.1、10.2 |
| 更换 harness / 插件 | 玩家 | — | 0 | 仅编队界面 | 战斗外 | 玩 4.4 |

> **基础行动不是免费最优解**：阶段二必须验算基础行动的输出显著低于 0–1 费卡，否则出现"永远普攻"。验证方法是三份手算样例（保守基础行动 / 积极出牌 / 高温爆发），见流 阶段二。
