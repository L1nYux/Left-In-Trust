## 0. 状态定义与改法

| 状态 | 含义 | 谁可以改 |
| --- | --- | --- |
| 已定稿 | 用户在两份 Word 或书面意见中明确写下，且未见矛盾 | 用户 |
| 冲突裁决（登记） | 两份资料口径不一致，本文按 §3 规则取一方，并留下出处 | 用户可推翻；推翻需在本文件追加记录 |
| **建议默认（可逆）** | 我方给出的最小改动方案，未获用户确认。程序按此实现，但文档与界面不得宣称"已确定" | 用户一句话即可改为其他选项 |
| **待用户决定** | 会改变核心玩法、产品定位或失败判定，我方只给推荐与影响，不擅自定稿 | **只有用户能定** |
| 暂缓 | 已存在于资料，明确不在当前三版本范围 | 用户可提前 |

编号规则：`D-xx` 决策；`Q1–Q5` 待用户决定问题；`A-xx` 我方假设；`X-xx` 口径冲突登记；`C-xx` 变更记录。

## 2. 待用户决定（Q1–Q5，共 5 条）

> 每条格式：现状 → 问题 → 选项 → 推荐 → 影响 → 何时能用测试回答。

### Q1 token 归零时，什么情况下立即失败？

- **现状引用**：《总览.docx》§5.1「使用卡牌、受到攻击均消耗 token，归零即失败」；《玩法.docx》§5.2「Token 归零即失败，这是唯一的失败判定」；《总览.docx》§10.2 学生被动「token 为 0 时仍可打出 1 张 0 费卡（每场 1 次）」；《玩法.docx》§5.2 卡费区间「普通卡 0–2，强力卡 3–5」；§4.2 单人基础 token 为 3。
- **为什么必须由你决定**：它决定"风险感"到底来自哪里，且直接改变所有卡费的可用性——按字面"花到 0 就死"，单人 3 token 下任何 3 费卡都是自杀，强力卡实际上不可用。
- **选项**：
  - **A（推荐）断电模型**：主动支付可把 token 花到 0，进入"断电"（本回合不能再付 token，只能基础行动与 0 费卡）；**只有受伤**把 token 降到 0 才判负。学生被动因此自然成立。
  - **B 保留底线**：支付不得使 token 低于 1（最后一枚 token 是"保命血"）。后果：3 费卡要用必须先把上限堆到 4 以上，卡费曲线要整体下移。
  - **C 字面执行**：任何原因归零都立即失败。后果：demo 第一场就无法打出 3 费卡；学生被动变成"免死一次"需要重写。
- **推荐 A 的理由**：唯一失败判定不变、token 兼生命值不变，只补一个"判负触发源"，改动最小；且让"花光还是留血"成为每回合的真实选择。
- **对三版本的影响**：阶段三即可验证（单场战斗），不需要额外美术或内容。
- **若你不表态**：按 A 实现，并在程序与文档中标注"待确认"。

### Q2 每场战斗开始回满 token，休息节点的"回血"还要不要？

- **现状引用**：《总览.docx》§4.2、§5.1「每场战斗开始时恢复至初始 token」；《玩法.docx》§5.1、§5.2 同；《玩法.docx》§5.2「战斗中不自动回满，回复来源为休息节点、卡牌、插件、过载状态」；《总览.docx》§3.2、《玩法.docx》§3.2「休息：恢复 token（兼作回血）；或删卡/升级卡/压缩为摘要卡」；《总览.docx》§13.2 已把休息节点列为定稿。
- **问题**：每战回满会让休息回血永远无效——刚回的血被下一场开始重置。
- **选项**：
  - **A（推荐）保留回满，休息不回血**：休息只做删卡/升级卡/压缩为摘要卡/微调；"回复量"这个待定项直接取消。
  - **B 改为战间损耗**：取消每战回满，token 跨场继承，休息/充值/商店负责回血。代价：需要重做章内经济、敌人伤害曲线、回复量，还要新增"跨场恢复"概念，系统数量上升。
  - **C 两者都留**：每战回满 + 休息可回"超出上限的临时 token"（如 +2，下场清零）。代价：多一层"临时生命"，UI 与教学成本增加。
- **推荐 A 的理由**：用户原文的每战回满写了两遍，且"token 是每场战斗内部的张力"这一定位最清楚；改 B 等于把 demo 从战斗游戏改成资源运营游戏。
- **对三版本的影响**：只影响休息节点内容与并行数值，不影响战斗原型。
- **若你不表态**：按 A 实现。

### Q3 共享 token 下，"热插拔不受伤"到底免什么？

- **现状引用**：《总览.docx》§6.3「主动热插拔下线：本回合不行动、不受伤，专属卡转为 API 调用模式，下回合回归」；《玩法.docx》§6.3 同；《总览.docx》§4.3「不设独立 HP，受到攻击直接扣全队 token」；《玩法.docx》§4.1「角色退场后不可行动、不可被选为目标」。
- **问题**：伤害落在公共 token 上，"该角色不受伤"没有对象；若解释为"下线能挡公共伤害"，三人全下线就等于无限免伤。
- **选项**：
  - **A（推荐）**：公共伤害不可规避；热插拔只免"只以该角色为目标"的定向效果；场上必须留 ≥1 在线角色；每角色每场限 1 次。
  - **B**：下线角色可为全队减免一定伤害（如每名下线角色让本次公共伤害 −1）。热插拔变成纯收益，容易变成"永远有人下线"的摆烂策略。
  - **C**：热插拔只转移行动权与卡牌状态，**没有任何防御收益**。最干净，但"不受伤"这句原文必须删改。
- **推荐 A 的理由**：保住"下线是个战术出口"的原意，同时关闭无限免伤与全员离线的死结；只补三条约束，不改失败判定。
- **对三版本的影响**：只影响阶段四小队阶段的敌人目标选择逻辑；战斗原型（单角色）不涉及。
- **若你不表态**：按 A 实现。

### Q4 "窗口占用"是指载入张数，还是已经打出的张数？

- **现状引用**：《总览.docx》§1.2「每次使用卡牌增加本回合上下文并消耗 token，该角色上下文越满 token 消耗越大」；§5.1「本回合窗口占用越高，后续打出的卡 token 消耗越大；达到上限后角色性能大幅下降」；《玩法.docx》§4.2 窗口 5/6/7；§5.1 载入"直到窗口达到容量或玩家选择停止"；`项目推进流程与AI提示词.md`「必须先处理的规则问题」要求「明确手牌载入容量与本回合已执行的上下文负荷如何关联，用两个数值示例走通；避免开局载满即过载」。
- **问题**：读数一（载入即占用）会让开局载满直接过载、第一张卡最贵；读数二（打出才占用）在单人局永远不触发（每回合只打 1 张）。两种读数都让机制在某些版本里失效。
- **选项**：
  - **A（推荐）拆两个数值**：W=载入容量（5/6/7）；L=本回合已执行张数（回合开始归零）。费用 = 卡面 + max(0, L − 上场人数)；L ≥ W 时本回合禁牌。单人局主要靠"载入几张"施压，2–3 人局才出现递增费用。
  - **B 载入即负荷**：载入张数直接计入 L。单人局立刻有压力，但"载满"变成陷阱，4.2 的 5/6/7 含义要重写，且"开局满手是否直接过载"需要额外豁免规则。
  - **C 只用容量，不做递增费用**：把"费用随窗口上升"降级为"L ≥ W 禁牌"。最简单、最好教学，但损失设计文档里明确写过的核心张力。
- **推荐 A 的理由**：最贴近原文措辞、不动 4.2 的数值；同时给出"用哪个数、怎么算"的可执行定义。B 留作阶段七的数据开关（D-21）。
- **对三版本的影响**：直接决定阶段二战斗规格的费用模块，是阶段三的前提。
- **若你不表态**：按 A 实现。

### Q5 打出的卡、没用完的卡、被遗忘的卡分别去哪？

- **现状引用**：《总览.docx》§6.1「打出的 buff 卡进入缓存区…最旧卡被遗忘，本场战斗内无法使用」；《玩法.docx》§6.1「打出的卡进入缓存区…最旧的卡被遗忘：本场移入离线区或本场移除」；§6.1 否定"抽牌堆→手牌→弃牌堆→洗回"循环；§7.2 退场专属卡移入离线区、回归洗回卡组。
- **问题**：①攻击卡打出后去哪没写；②缓存里的卡能不能再打没写；③遗忘的卡与离线区的卡混为一谈，导致"遗忘"可以被下线-回归白嫖回来；④没用完的窗口剩牌怎么处理会让"归零"破功或形成抽牌死循环。
- **选项（推荐组合即 A）**：
  - **A（推荐）**：所有打出的卡进缓存且**不可再打**；缓存上限 4，超限最旧进**遗忘区（本场移除，不可回收）**；强力卡打出直接进遗忘区；回合末未打出的自家卡回**卡组底**，污染卡进遗忘区；离线区只存退场角色专属卡，回归时洗回卡组，与遗忘区互不迁移。
  - **B 只让 buff 卡进缓存**：攻击卡打出即离场。缓存压力小、遗忘少见，代价是"注意力预算"的味道变淡。
  - **C 缓存可重复打出**：缓存变成第二手牌。会让"遗忘"几乎不可能发生，且与"上下文已执行"的叙事冲突。
- **推荐 A 的理由**：一个统一的区域规则 + 一条防循环例外（强力卡），实现与教学成本最低，同时保住"会遗忘"这一差异化。
- **对三版本的影响**：阶段三就要实现（缓存/遗忘是原型必做项）。
- **若你不表态**：按 A 实现。
