# 未尽之托 规则基准

版本 v0.8，2026-10-27。本文件是当前执行规则；[战斗规格](战斗规格.md)补充时序，[首批内容.json](首批内容.json)定义数值。旧规则全文已备份，不再在本页混排。v0.6 把“每名角色每回合一次行动”改为不限行动次数，基础动作各限一次；首批数值与卡牌未随本版重调。用户已有方向继续保留，本轮新增数值与卡牌是授权优化下采用的设计默认，不等于试玩定稿。v0.7 按用户裁决允许 1–3 个敌人实例、群攻、多阶段、意图伪装、分裂/合体与随机目标等结构（§10），首批 Demo 不实现。v0.8 按 Q01 裁决在首批 Demo 增加一只双体普通怪（§10 例外，见 §11），其余与 Q02–Q05 相关的机制见 §11 与[评审与补强](../多目标战斗与超常机制设计方案_评审与补强.md) §十四。

## 1 核心规则

| 编号 | 当前规则 |
| --- | --- |
| R01 | 每人独立 token，兼生命与出牌费用，余额跨战继承；上限默认 12 |
| R02 | 使用者支付，受击者承伤；合法支付后至少剩 1，不借用队友、不用本次回复垫付 |
| R03 | 一人归零下线；全上场归零即本局失败，健康替补不自动救场 |
| R04 | 每回合全队抽五张；每名在线角色每回合可行动任意多次，受手牌、合法目标与个人 token 余额限制；基础攻击与基础防御为免费基础动作，每名在线角色每回合各限 1 次；玩家自行决定角色与出牌顺序，敌方顺序预告 |
| R05 | 普通抽弃洗回；消耗与下线封存分开；战后从局内牌组重新建牌，状态清空 |
| R06 | 胜利一次给所有正余额已入队成员含替补各 +3；0 不复起，入场不回满 |
| R07 | 防护归目标个人，逐段抵伤，回合末清除；锁定目标下线后不转火 |
| R08 | 战外免费编队，1–3 名正余额成员；局内队伍长期上限 6，Demo 只有三名可用角色 |
| R09 | GPT 连攻、Claude 定向保护反击、DeepSeek 白饭；Kimi 记录仅属后续个人机制 |
| R10 | AI 同行明线与“我”的现实暗线；对白依任务已知信息，不读取未收到的现实片段 |
| R11 | 每章随机任务对应一个 Boss；阶段专属关底概率替换最后章底；高难隐藏“我”额外追加 |
| R12 | 人生阶段与 AI 分开；阶段影响叙事与遭遇资格，不恢复旧身份技能和钱包差异 |

## 2 行动与结算

每回合全队抽五张；每名在线角色每回合可行动任意多次，直到手牌、合法目标或个人 token 余额不足，玩家自行决定角色与出牌顺序。同回合可连续出牌，同一角色先出牌再出牌、或多人交替出牌都合法，不因“本回合已行动”而拒绝。免费基础攻击 3、基础防御给自己防护 3 是不耗 token 的基础动作，每名在线角色每回合各限 1 次；重复使用本回合已用的基础动作整体拒绝。专属牌只能由所属在线角色使用。胜利条件是所有敌人生命归零（首批单敌即击杀）。最后敌人被击败立即胜利，不能再补血。多体结构下敌人从左到右依次行动，每个敌人的目标在预告期随机锁定并在 UI 显示“随机目标”标记（§10 A06/A07）。每一步付费与全部目标检查在任何状态变更前完成；非法操作不扣费、不耗行动、不消耗卡、不触发被动。敌人仍每回合只结算一次意图。GPT 基础动作、非攻击牌与跳过都会断连击；行动不限次数后，GPT 连击点可在同一回合内叠到 2（如 G1→G1→G2 连发）。

Claude 本回合提供过正数防护的对象在敌方阶段实际挡伤，且自己仍在线，获得反击就绪；不追踪消耗的防护来自谁。同一回合可给多个目标施放定向防护，仍受牌数与 token 限制。下一次攻击的一段 +4，基础攻击可用，最多存一次。未获得新反击时，旧就绪保留至兑现、下线或战斗结束。多体结构下反击优先回打攻击来源；来源已死亡则改选最左存活敌人（§10 A08）。

DeepSeek 每个仍在进行的在线回合末 +1 白饭，最多三层。“稳住火候”行动时另 +1，故不再采用“最快第四回合”的旧绝对时点；同一回合反复行动不会多叠白饭。“提早开饭”每层换 2 伤害并清空，覆盖该牌的满层 +6，不叠加；其他卡面费至少 2 的攻击仍满层 +6。

## 3 牌组与恢复

初始十二张实体牌，配方见战斗规格；基础设计十二种。战外总牌组最少八张，战内封存导致少于八张合法，不免费补牌。每张牌一个独立 ID，升级保留 ID，任一时刻只在一个区域。

回复受个人上限截断。战内只给在线者回复；转交须另一名在线者有至少 2 缺口，支付 2、回复 2，升级只额外给目标防护 2。应急补给牌组最多一张，本战消耗，不复制、生成或回收。

休息一次三选一：单人 +6、升级一张、删除一张。商店每店一次花 6 算力单人 +4；满额不可购买。战外回复可选 0 token 者。普通战 +4 算力，精英/Boss +8。每战奖励三选一可跳过，事件当前只有文本与线索。全部恢复与奖励一次性结算。

## 4 招募与规模

非最后章 Boss 胜后一次招募。候选为已制作且未入队，包含尚未永久解锁者，避免“先解锁才进池”的死循环。新成员满额入队，不重复领取刚结束战斗的 +3。终章及隐藏前不新增招募。

附赠两张不同基础专属牌，每张可加入、替换一张非消耗牌或放弃。跳过招募可升级两张不同未升级牌，不足部分每张折 4 算力。每张仅升一级，不降费用。收益等价性仍待测试。

两章正常流程从一人到最多两人；三人阵容在独立测试场与未来长流程验证。未招募者不参与本轮现场对白；正余额替补可在战外发言，战内仅在线者发言，0 token 者仅在局外回顾发言。

## 5 随机与收藏

进入章节时保存任务、Boss、敌人版本、随机状态与事件选择。地图、牌库、奖励、演出分开随机流，播放台词不影响抽牌。任务池先过滤阶段与章节，空池使用同阶段同章后备；不跨阶段顶替专属 Boss。

收藏内容键为 stage/task/outcome/variant，不含 runId、attemptId 或文件版本。尝试号只作为获得记录；修字不新增收藏，实质新场景才新增 variant。成功、准备失败、验收失败分别登记。事件键为 runId/nodeId/outcome；同节点不能同时胜负。

主要结局读取事实集合与语境组，不拼接平行人生中互斥的人名日期。Demo“暂存明天”要求同一阶段的 work_value 与 someone_waiting，两事实均有纯胜利路径；资格持久保存，玩家在合法收束点选择结局。

## 6 难度与隐藏战

基础 Demo 为 D=0，挑战内容关闭。挑战规则实验 D=0–3、T=1；已有常规通关且 D>T，最后章底后必定追加“我”，D=T 不触发。阶段专属概率 25% 同属实验配置，未证明正式平衡。完成最高已开放档的常规流程后开放下一档，实验上限 3；隐藏失败仍保留普通通关进度。

阶段专属仅挑战配置启用，概率替换最后章底，只抽本阶段。普通与专属之后均可追加隐藏，无指定 AI、全收藏或第二次概率门槛。隐藏前只做既有编队和一次正常奖励，继承章底胜后余额，不回满、不复活。

隐藏入场锁定人生阶段、已入队名单、上场阵容与脚本。每回合至多一个主意图及一个修正，提前显示最终各段值；不直接禁用连击、反击、白饭。隐藏失败保留收藏与已解锁结局；常规完整结局演出等待隐藏结果。

## 7 停用与保留方向

停用公共温度、负荷、共享 token、全队缓存、速度轴、战内热插拔、离线 API、身份主动技能、自动复活、章节重录与协议值。性格缺点不随机剥夺玩家行动。

长期保留六阶段、十六角色、长流程、GPT 满级一次 Astra/Image2 二选一、DeepSeek 女仆/大肥鱼与不限插件方向、Kimi 两槽私有记录。初版插件与 harness 不进入掉落池，未来先解决装卸套利再启用。

## 8 维护

改规则、卡值或剧情资格时同步数据、规格、决策及验证。历史 v0.2–v0.5 结果不累计为本版通过；v0.5 的数值与卡牌仍沿用，但按“每角色一次行动”得出的节奏与胜率结论作废，需按 v0.6 重跑。自动验算、真实存档、故障恢复、可玩界面、真人体验各列证据。

## 9 待确认的设计建议

以下随不限行动出现，尚未确认，不构成执行规则：

- 基础动作各限一次是当前折中；是否再加“每角色每回合最多 N 次行动”或费用递增，待试玩数据。
- 不限行动会缩短 Demo、放大连击爆发，敌人节奏与数值需要重调；本轮不改首批内容.json。
- 拖拽出牌的落点判定、回弹动画与键鼠/触屏适配尚未验收。

## 10 允许结构（v0.7，首批 Demo 不实现）

用户裁决 R01：现行规则与工程基准改为允许以下结构，但首批 Demo 不要求实现，也不在 `首批内容.json` 预埋未实现字段。

| 编号 | 允许结构 |
| --- | --- |
| A01 | 多敌人：一场战斗可有 1–3 个敌人实例，按左/中/右槽位排布；可分体定义生命，也可共享组生命池 |
| A02 | 群攻：允许一段攻击命中多个敌人或全队，须在预告期展开到具体目标，结算时不得补选 |
| A03 | 多阶段：敌人可在生命区间或回合节点切换 pattern 组；切换必须公开，不重置已受损防护 |
| A04 | 意图伪装：允许意图在 UI 显示区间或问号；规则层真值仍在预告期锁定，校验类牌可揭示真值 |
| A05 | 分裂/合体：视为行动，占用该敌人当回合动作；分裂/合体后目标与段数在预告期重算并公开 |
| A06 | 敌方行动顺序：同一回合内从左到右依次行动；单敌仍按原 pattern，多体共享回合计数 |
| A07 | 目标随机：多体结构下每个敌人的目标在预告期随机确定并锁定，UI 显示“随机目标”标记 |
| A08 | Claude 反击归因：优先反击攻击来源；来源已死亡或不存在时反击最左存活敌人 |

首批 Demo 原为单敌人、单段攻击；v0.8 按 Q01 裁决新增一只双体普通怪「未归档的草稿」（§11），因此 `parts[]`、全灭判定、随机目标、逐体行动必须在首批 Demo 实现（仅此一怪使用）；其余结构在实现前不得作为验收依据。实现顺序与验收见[设计评审与补强](../多目标战斗与超常机制设计方案_评审与补强.md)十一节。

## 11 后续机制（v0.8 方向，首批 Demo 不实现）

用户 2026-10-27 Q01–Q05 裁决结果。详细设计见[评审与补强](../多目标战斗与超常机制设计方案_评审与补强.md) §十四与[战斗规格](战斗规格.md) §8。

- **Q01 Demo 新怪**：「未归档的草稿」双体普通战，单人 2×13 HP，草稿继承 +2/双杀奖励 +1 token 与 +1 算力；路线放在“缺失附件 → 可选休息 → 未归档的草稿 → 本次提交版”之间。
- **Q02 意图伪装**：某精英怪专属机制（暂定「脱敏审计」，30 HP，每战最多 2 回合），不进首批 Demo；校验牌 V/C2 可揭示。
- **Q03 8-bit**：正式版先做演出、再做事件房，可玩平台跳跃版留作后续特殊战；首批 Demo 不出现。
- **Q04 命名**：《评审与补强》§十二 的新名正式采用。
- **Q05 机制取舍**：C1 上下文窗口、C2 提示词注入、C3 温度采样作为常驻机制保留（默认不启用，试点顺序 C3 → C2 → C1）；C4 工具调用弃置；C5 记忆投影改为「答辩委员会」专属 Boss 机制，不作通用机制；C6 规则补丁与 C7 评测门禁合并为「契约」——精英或 Boss 战前小概率（暂定 20%）出现三选一：每组为“本场约束 + 胜利后永久规则补丁”，失败无奖励且约束照常。
