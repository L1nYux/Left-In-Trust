## 3. 十个指定主题的逐条结论（行号级）

1. **非法操作原子性**：一致。`_validate_action`（`game_rules.gd:314-351`）在 `try_action`（`:174-213`）任何改动前完成；A 组 13 条非法序列 `state_same=true`，错误码与预期逐字符一致。`preview_action`（`:135-172`）复用同一校验，预览不可能出现「看起来合法、执行却失败」。附带风险：`main.gd:260-263` 的 finish 失败静默 return，属 UI 层（C-05），规则层不受影响。
2. **支付后保留 1**：一致。`:346-350` 校验 `token - cost >= 1`，`:195` 才扣费；B 组阈值 cost0/1/2 → 1/2/3。T 先扣后给（`:205`）在同一校验通过后原子完成。
3. **目标下线后的多段攻击**：一致。意图在 `begin_turn` 用 `_rotating_online_target`（`:399-407`）锁定并展开（`:125-131`）；`resolve_hit`（`:250-273`）对离线目标写 `skipped` 事件、不转火。实测 shield 5 对 3+3 → 吸收 3,2，掉 1；目标中途归零后余段 skipped。
4. **击杀停手**：一致。`:210-212` 置 `result="win"`；`finish_turn`（`:215-248`）在 result 非 ongoing 时不结算敌方/不再补给；`main.gd:282` 有 debug 断言（release 构建会被剥离，故矩阵以规则层断言为准）。算力/胜利恢复只在 `settle_battle`（`:275-294`）发。
5. **牌实体守恒**：一致。五区（draw/hand/discard/consumed/sealed）整场每步断言总数 == `total_cards` 且 uid 唯一；R 进 consumed 不回牌池（`:384` 附近的移动逻辑）；洗回只从 discard 取（`:389-397`）。实现无显式不变量断言，属可加工程项（不影响行为）。
6. **下线封存**：一致（按当前假设 C-01）。`_seal_owned_cards`（`:378-387`）只封 `owner == 下线者` 的牌；单人 GPT 实测封存 3 张、通用 9 张留队、后续回合不再抽到。**若用户意图是「下线者全部牌封存」，需在修 S-01 时一并改这里**。
7. **战后恢复**：一致。`:286-291` 只对正余额成员 +3 并截断到 max，0 不复起；入场 `start_battle` 读 run 账本不回满；duplicate/冲突/失败后 ended 均已实测；战后下一战重建牌组（`:68-92`）。
8. **GPT 连击**：一致。加成读操作前 streak（`:141-152`），G2 满层额外 +2 只给 G2（`:157` 附近）；基础动作与非攻击牌断连击（`:184-193`）；上限 2；跨回合保留；升级后满层 18。
9. **Claude 反击**：一致。`resolve_hit` 仅在「受保护对象 + 实际挡伤>0」时向保护者登记（`:258-272`）；回合末结算（`:226-239`）要求 Claude 在线；`preview/try` 对攻击一段 +4 并消耗（`:153-172`/`:195`）。已实测 7/9/8/10/14、只兑现一次、不叠加、跨回合保留、下线清空。
10. **DeepSeek 白饭**：一致。`begin_turn` 重置/`finish_turn` 回合末 +1（`:226-239`），S1 行动 +1（`try_action` 被动段），S2 cashRice 8+2×层清空，cost≥2 攻击满层 +6 后清空（`:141-152`、`:195-207`）。击杀/离线/失败回合不产。

## 4. 缺陷清单（可复现）

### S-01（中，切片外触发）多角色 run 的初始牌组只由第一名角色生成

- 位置：`game_rules.gd:47`（`"deck": make_starting_deck(str(role_ids[0]))`）；对照 `:34-53` 的 `make_run_for_roles`、`:75-79` 的入场过滤。
- 前置：`make_run_for_roles(["GPT","Claude"], 20261025)`。
- 操作：检查 `run.deck`；或 `start_battle(run, "b", ["Claude"], "missing", 1)` 后看手牌。
- 预期：24 张（两人各 12 张，含 G1×2/G2/C1×2/C2）；Claude 可抽到 C1/C2。
- 实际：12 张，owner 统计 `{"-":9,"GPT":3}`；`start_battle(...).total_cards=12`；Claude 只有基础动作。
- 违反：`docs/战斗规格.md:9`（入场筛掉替补专属牌再洗牌）、`docs/卡牌表.md:24`、R08 编队 1–3 人。
- 失败表现：第二名角色无专属牌、专属被动空转；若只上第二人，牌组仅 9 张（少于规格最小体验）。
- 影响：主 UI 单人不可达；双人/多角色玩法接入前必须先修（否则同时会掩盖封存范围 C-01 的验证）。
- 修复入口（不在本轮执行）：`make_run_for_roles` 为每名队员各建 12 张并用角色前缀区分 uid；`start_battle` 过滤逻辑保留。

### S-02（中低，切片外触发）未结算的已结束战斗可重开；规则层无战斗实例登记

- 位置：`game_rules.gd:56-57`（只查 `run.ended` 与 `run.nodes.has(battle_id)`）。
- 前置：`start_battle(run,"ordinary",["GPT"],"missing",6)` → `begin_turn` → 把 GPT token 打到 1 → `resolve_hit` 造成 1 点伤害 → `result="loss"`，但**不调用** `settle_battle`。
- 操作：再次 `start_battle` 同一 `battle_id`。
- 预期：拒绝（战斗实例已存在/已结束，须先结算；规格 §1「已结算战斗不能重开」、§2.6「最后一名在线成员归零本局失败」）。
- 实际：成功重开；且可传新 `battle_seed`，等于「失败未结算 → 重 roll 抽牌与敌方意图 → 直到胜利再 settle」，产生逃逸/悔棋与重复发奖窗口。
- 失败表现：同一节点可被反复开战；结算顺序依赖调用方自律，主 UI 之外不可信。
- 修复入口：run 内维护 `battles` 登记（start 时占位，settle 时校验一致）；`start_battle` 拒绝「该 node 已有未结算或已结算战斗」。

### S-03（低）局结束后休息接口返回 `service_used`，UI 无该文案

- 位置：`game_rules.gd:297-298`（`run.ended` 与 `services.has(node_id)` 共用一个错误码）；`main.gd:320`（`_show_fatal("休息失败：%s" % result["error"])`）、`main.gd:379-390`（文案表无 `service_used`）。
- 前置：run 已失败/结束（`ended=true`）。
- 操作：`rest_recover(run, "rest", "GPT")`。
- 预期：拒绝，错误语义为「局已结束」；UI 显示中文可读文案。
- 实际：返回 `{"ok":false,"error":"service_used"}`，UI 显示「休息失败：service_used」。
- 失败表现：错误码语义错误、暴露英文内部码；不影响状态正确性。主 UI 正常流程不可达（局结束后不再进休息页）。

### S-04（低，潜在）手牌按钮使用未升级的基础定义

- 位置：`main.gd:193`（`rules.card_defs[card["code"]]`）；对照 `game_rules.gd:353-358` 的 `_resolved_card`。
- 前置：卡牌升级（未来入口；当前起始牌 `upgraded=false`，无升级入口）。
- 操作：渲染手牌按钮。
- 预期：显示升级后的伤害/防护/回复/费用。
- 实际：显示基础定义数值（预览面板走规则层解析，可能出现「按钮数值与预览不一致」）。
- 失败表现：升级后 UI 展示旧值，玩家误判；当前不可复现，接入升级（B-08）时必修。
