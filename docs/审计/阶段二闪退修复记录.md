# 阶段二闪退修复记录

日期：2026-10-25

## 现象

Windows 版本在进入编队、选择角色、选择或确认行动等交互点偶发进程退出。这些路径都会由 Button.pressed 信号触发整屏 UI 重建。

## 根因与修复

旧实现的 _new_screen 在 pressed 回调尚未返回时，对包含当前按钮的整棵节点树直接调用 free。立即销毁正在派发信号的对象树存在生命周期风险，而且原 UI 自动测试直接调用控制器方法，没有真实发射按钮信号，因此没有覆盖这一边界。

修复内容：

- main_stage2.gd 与旧 main.gd 的整屏切换改为先 remove_child，再 queue_free。
- 当前屏幕立即脱离场景树，但对象销毁延迟到本轮信号派发完成之后。
- 新增 test_ui_clicks.gd，通过 Button.emit_signal("pressed") 走真实信号链。
- 压力测试连续执行 12 轮“进入编队 → 选择两名角色 → 开始战斗 → 选择并确认两次行动 → 结束回合”。
- 一键阶段门禁加入 ui-click-tests，并生成独立日志。

## 验证

- UI CLICK TESTS：12 轮信号驱动切换全部通过。
- 完整阶段门禁：data-sync、Node、rules、audit、smoke、UI flows、UI clicks、multiplayer、save 全部 PASS。
- 重新导出的 Windows EXE 无参数正常启动后持续运行 5 秒，未自行退出。
- Windows EXE 的 GPT＋Claude 自动流程退出码 0，ordinary 与 boss 均 win，最终算力 12。

当前受限执行环境会报告无法创建 user://logs 与 shader cache；该错误不会导致进程退出。Windows 事件日志读取因系统权限受限，未取得系统级崩溃转储，因此根因判断来自共同调用路径、生命周期风险与修复后的信号压力测试。
