## 探针设计要点（可复核性）

- 每个断言都直接调用 `GameRules.make_run_for_roles / start_battle / begin_turn / try_action / preview_action / finish_turn / resolve_hit / settle_battle / rest_recover`，期望值全部来自规格文档原文，而不是从实现反推。
- A 组、L 组每个拒绝场景都在调用前后取 `JSON.stringify(state)` 快照比对，用 `state_same=true/false` 直接量化“无任何状态变更”。
- E 组在整场脚本化战斗的每个阶段（begin / 每次行动 / finish）都调用 `_conservation`：`draw+hand+discard+consumed+sealed` 总数必须等于 `total_cards`，且全部 uid 唯一。
- 反例断言同时打印实测值（错误码、剩余 token、手牌/牌区数量），失败时可以据此还原最小调用序列；本次无 FAIL，无需列最小复现片段。
- 断言比较为逐字符相等（预期/实际均为 ASCII 实测串），任何数值漂移都会直接暴露。
