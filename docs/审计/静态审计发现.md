## 1. A 缺陷清单

### S-01 多角色 run 的初始牌组只由第一名角色生成

- **位置**：`game_rules.gd:47`（`"deck": make_starting_deck(str(role_ids[0]))`），相关 `game_rules.gd:34-53`、`game_rules.gd:76-79`。
- **违反条款**：`docs/战斗规格.md:9`（"开局：A×3、D×3、H×2、R×1、基础专属一×2、基础专属二×1，共十二张"——按参战角色各一套）；`docs/卡牌表.md:24`（"每位开局角色十二张…本人第一专属×2、第二专属×1"）；`docs/规则基准.md:16` R08（战外编队 1–3 名成员）。
- **级别**：中。**可达性：切片外**。`main.gd:136` 恒传 `[selected_role]` 单人，主 UI 不触发；但 `make_run_for_roles` 是公开 API，且 `docs/战斗规格.md:35` 要求第二章双人扩编，接入多人即触发。
- **最小复现**（headless，`--path game`）：

```gdscript
var rules := GameRules.new(ContentDB.load_content())
var run := rules.make_run_for_roles(["GPT", "Claude"], 20261025)
print(run["deck"].size())                                  # 实际 12；预期 24
print(rules.make_starting_deck("Claude").size())           # 12（说明单人函数本身正确）
var owners := {}
for inst in run["deck"]:
    var owner: String = str(rules.card_defs[inst["code"]].get("owner", "-"))
    owners[owner] = int(owners.get(owner, 0)) + 1
print(owners)                                              # 实际 {"-": 9, "GPT": 3}；Claude 键缺失
var st := rules.start_battle(run, "duo", ["GPT", "Claude"], "missing", 1)
print(st["total_cards"])                                   # 实际 12；预期 24
# st 的 draw+hand 中 code=="C1"/"C2" 的实例数：实际 0
```

- **预期 vs 实际**：预期 lineup 内每名角色的十二张（含本人专属）都进入局内牌组；实际只有 `role_ids[0]` 的十二张，第二、三名角色没有专属牌，因此 `game_rules.gd:76-79` 的"筛掉替补专属牌"过滤对后续成员永远无事可做，Claude 在双人战中只能出基础动作。
- **附带影响**：S-01 使"下线封存范围"（C-01）在多角色下无法被最终验证——因为缺少 Claude 专属牌，`_seal_owned_cards` 没有可封的对家牌。

### S-02 未结算的战斗可重开；规则层无战斗实例登记

- **位置**：`game_rules.gd:56-57`（唯一守卫 `run_state["nodes"].has(battle_id)`）；`game_rules.gd:102`（`run_state["started"] = true` 只写不读）；`game_rules.gd:275-294`（只有 `settle_battle` 才把结果写入 `nodes`/`ended`）。
- **违反条款**：`docs/战斗规格.md:9`（"已结算的战斗不能重新打开"）的执行前提——当前实现只拦"已经写入 `nodes` 的 id"，未拦"战斗已开始且已分胜负但未结算"；`docs/战斗规格.md:41-43`（胜利/失败事务一次性写入终态）。
- **级别**：中低。**可达性：切片外**。`main.gd:260-276` 失败与 `main.gd:278-288` 胜利都会调 `settle_battle`，主 UI 不可达；属规则层健壮性缺口（调用方漏结算即可绕过终态）。
- **最小复现**：

```gdscript
var rules := GameRules.new(ContentDB.load_content())
var run := rules.make_run("GPT", 6)
var st := rules.start_battle(run, "ordinary", ["GPT"], "missing", 6)
rules.begin_turn(st)
st["accounts"]["GPT"]["token"] = 1
var ev := rules.resolve_hit(st, "GPT", 1)      # token 归零：online=false，result="loss"
print(st["result"])                            # "loss"
# 故意不调用 settle_battle
var again := rules.start_battle(run, "ordinary", ["GPT"], "missing", 6)
print(again.has("error"))                      # 实际 false（开出一场新战斗）；预期 true
# 对照：结算后重开会被正确拒绝
rules.settle_battle(run, st)
print(rules.start_battle(run, "ordinary", ["GPT"], "missing", 6))  # {"error":"run_or_node_finished"}
```

- **预期 vs 实际**：预期"战斗一旦开始，未结算不得重开；已结束的战斗必须先结算并写入终态"；实际只要不调 `settle_battle`，同一 `battle_id` 可无限重开，且同一敌人换一个 `battle_id` 还能再战再结算、拿第二份算力（`game_rules.gd:291`）。探针结果：`T11.restart_unsettled_loss_rejected` FAIL。
- **修复方向（仅指位置，不含玩法改动）**：在 run 上登记进行中的战斗实例（如 `run["active_battle"]`），或在 `start_battle` 时检查 `run["started"]` 与已结束未结算状态。

### S-03 休息接口把"局已结束"报成 `service_used`，且 UI 无该文案

- **位置**：`game_rules.gd:296-298`（`if run_state.get("ended", false) or run_state["services"].has(node_id): return _failure("service_used")`）；`main.gd:317-321`（`_show_fatal("休息失败：%s" % result["error"])`）；`main.gd:379-390`（`_error_text` 只映射 8 个 code）。
- **违反条款**：无直接条款（规格未定义错误码），但导致读者可见的错误信息与事实不符；`docs/规则基准.md:36` 的休息语义是"一次性结算"，与"局已结束"是两种不同原因。
- **级别**：低。**可达性：切片内不可达**（败北后 `main.gd:270-273` 直接进结果页，休息按钮不再出现），但两条代码路径真实存在。
- **最小复现**：

```gdscript
var rules := GameRules.new(ContentDB.load_content())
var run := rules.make_run("GPT", 6)
var st := rules.start_battle(run, "n1", ["GPT"], "missing", 6)
rules.begin_turn(st); st["accounts"]["GPT"]["token"] = 1; rules.resolve_hit(st, "GPT", 1)
rules.settle_battle(run, st)                       # 败北：run["ended"]=true
print(rules.rest_recover(run, "rest", "GPT"))      # 实际 {"ok":false,"error":"service_used"}
                                                   # 预期可区分的原因（如 "run_ended"）
```

- **预期 vs 实际**：预期 UI 能显示"委托已结束"，实际会显示原始 code `service_used`（且 `main.gd:380-389` 未收录该 code，`_error_text` 原样返回英文串）。

### S-04 手牌按钮使用未升级的基础定义（潜在，切片内不可复现）

- **位置**：`main.gd:191-194`（`var definition: Dictionary = rules.card_defs[card["code"]]`），对比 `game_rules.gd:353-358`（`_resolved_card` 才应用 `upgrade` 增量）。
- **违反条款**：`docs/卡牌表.md:9-20`（升级后的伤害/防护值）与 `docs/规则基准.md:32`（升级仅按定义增量）；界面应显示已升级值。
- **级别**：低（潜在）。**可达性：切片内不可复现**——起始牌组全部 `upgraded=false`（`game_rules.gd:28`），且切片无升级入口（B-08）；一旦接入升级入口，按钮/预览文案会显示基础值（如 A 显示 6 而非 8）。
- **最小复现**（构造升级实例后渲染）：

```gdscript
var card := {"uid": "GPT-00", "code": "A", "upgraded": true}
print(rules.card_defs[card["code"]]["damage"])          # 6（main.gd:193 会用它显示）
print(GameRules.new(ContentDB.load_content())._resolved_card(card)["damage"])  # 8（规则层实际结算值）
```

- **预期 vs 实际**：预期界面显示 `_resolved_card` 的结果；实际用的是基础定义。
