## 2. 校验方法

### 2.1 机器校验（`_build/validate_story.cjs`）

解析每个 `<!-- event ... -->` 头及其后段落，检查：

- **头字段**：`id` / `chapter` / `task` / `stage` / `node` / `type` / `facts` / `knowledge` / `focus` / `boss` / `see` 齐全；`id` 形态为 `ch{1,2}.{task}.{stage}.{node}`、章级 `ch{n}.{stage}.{node}`、全局 `global.*`，且与 `chapter` 前缀一致。
- **枚举**：`node`（prologue/open/N1/N2/N3/B1/B2/rest/shop/event/boss/stageBoss/hidden/close/recruit/success/prepFail/acceptFail/ending/recap/appendix）与 `type` 合法，且 `node → type` 映射固定（如 N1→brief、N2→check、N3→accept、success/prepFail/acceptFail→reality）。
- **事实授予**：`success` 必须且只能给本章语境事实（第一章 `work_value`、第二章 `someone_waiting`）；`acceptFail` 只能 none 或本章事实；其余节点不得给事实。
- **Boss 映射**：第一章 `submit`、第二章 `recipient`、阶段专属 `stage_student` / `stage_employee`、隐藏 `hidden`；`B1` / `B2` 不得写成 Boss。
- **结局分支**：`ending` 必须带 `branch`，且两阶段都有 `eligible` / `not_eligible`。
- **发言人**：只允许 GPT / Claude / DeepSeek / 旁白 / 终端 / 我 / 敌人 / 系统；「我」只出现在 ending 与 hidden；「敌人」只出现在 battle；「终端」不得出现在 reality 片段。
- **段落完整性**：剧情/接单/核对/验收/休息/商店/事件/结局需「场景 + 三角色主句」；战斗另需「固定台词」；现实片段需「演出 + 旁白（≤2 句）+ 按在队角色收束」。
- **长度与重复**：台词单句过长、单条过多、同事件重复台词给警告。
- **覆盖**：8 组「任务 × 人生阶段」的 open/N1/N2/N3/success/acceptFail；每章每阶段的 B1/B2/boss/prepFail/close/rest/shop/event；第一章每阶段 recruit；第二章每阶段 stageBoss 与 hidden；序章；`global.future.01–06`；每个现实片段对应的 `global.recap.*`；id 唯一。

### 2.2 写作口径核对

对齐 [创作基准](00_创作基准.md) 与 [剧情大纲](../../剧情大纲.md) v4：

- 明线交付、暗线人生片段分离；三名 AI 只根据收到的任务、材料与反馈说话，不预知「我」的私人生活；未招募角色不插话。
- 每个任务的「关键发现者 / 判断失误者 / 补救者」按章轮换，不用固定强弱排序（report→DeepSeek 发现、Claude 差点只核数字；slides→GPT 发现、DeepSeek 自认删过来源；invite→Claude 发现备注所指、GPT 失误；photos→DeepSeek 发现同名不同天、Claude 把推测写成已知）。
- 轻喜剧都有起因、人物解法、结果，笑点来自材料与设备（示例页多吐一张、自动翻页计时器、压缩预览、空日期框），不靠角色降智。
- 现实片段只用规定物件与短句，不哭跪砸桌，不把老师、上级、朋友「我」怪物化；失败片段保留具体缺口。

## 4. 已知限制与未验证项

1. **未接入游戏**：117 个事件仍是 Markdown 文本与数据头，`game/` 尚未读取；单/双人抽句、在场成员过滤、`seenKey` 去重、跳过只跳演出等播放逻辑未实现、未联调。
2. **未真人试玩**：节奏（每节点 3–6 句、Boss 3–8 句、结局 8–14 句）、笑点是否成立、记忆剧场演出时长与可读性未做人工评审；台词自然度只做了静态口径核对。
3. **共享章级文本**：第一章 B1/B2、第二章 B1/B2/boss/prepFail/close 按「章 × 阶段」写一条，播放时需由接入层按当前任务替换材料名词；这属于数据设计取舍，不是缺事件。
4. **单 AI / 下线、0 token 情况**：脚本按「在场取一句、搭档取一句」与「fallback」设计，但具体回退顺序仍需接入层实现并验证，例如只剩一名 AI 时搭档回应应整段跳过。
5. **平衡与结局资格**：隐藏「我」与「暂存明天」的文本按 v0.5 资格模型写，未在新文本下复跑数值；挑战配置默认关闭，阶段专属 Boss 文本不能当作已平衡内容。
6. **长期附录**：`global.future.01–06` 只是六个长期结局方向，不是本轮实现文本，不应被当作文本完成度计入。

## 5. 复现

```powershell
node _build/assemble_story.cjs          # 重新拼装 docs/Demo剧情脚本.md
node _build/validate_story.cjs          # 完整校验（格式 + 覆盖），PASS 时退出码 0
node _build/validate_story.cjs --draft --file _build/story_drafts/第一章.md   # 单份草稿只查格式
```

校验输出同时保存到 `_build/story_validation.log`。重新拼装后需重跑校验，并更新脚本末尾「校验记录」一节与本报告第 3 节。
