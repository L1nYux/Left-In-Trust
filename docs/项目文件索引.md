## 3. 当前可玩 Demo

常规流程：标题 → 1–2 人编队 → 序章/任务开场 → 第一章路线图（图标节点） → “缺失附件”普通战 → 核对/可选休息 → Boss 前验收 → “本次提交版”Boss 战 → 胜负片段/结算。演出可继续或整段跳过；地图提供最近剧情回看和按在队成员筛选的旅途闲聊。

独立测试场：三人编队 → 单场完整战斗 → 结算。三名角色共用手牌；费用、生命、防护、被动与行动次数各自独立，每名在线角色每回合可行动任意多次，基础攻击与基础防御各限每回合 1 次。

出牌为拖拽到目标（攻击拖敌人，防护/恢复/转交拖友方，自身目标拖自己，非法落点弹回）；拖动时卡牌留在原位抬起高亮，并从卡牌拉出弧形箭头指向光标（仿《杀戮尖塔》）；卡面显示名称、小幅插画与左上角费用数字，悬停只显示归属和紧凑数值效果；右下发送箭头结束回合，战斗与地图右上角暂停按钮打开设置层（含“返回标题界面”）；结算页只显示标题与队内角色名。

当前优先实现：三名角色正式立绘、两名 Demo 敌人正式立绘、纸页旷野战斗场景、清晰战斗 UI、第一章路线图、1–3 人完整战斗与存档恢复。

仍未接入：新动效制作、音效/BGM、战斗结算专属台词、商店、招募、收藏、第二章与挑战/隐藏战入口。117 个剧情事件已进入运行数据，但目前只有第一章固定路线所需节点可达；扩展身份不套用学生/员工现实片段。

## 4. 修改检查

1. 数值变化先改 `docs/首批内容.json`，再运行 `_build/sync_game_data.ps1`。
2. 剧情变化先运行 `_build/validate_story.cjs`，再运行 `_build/export_story_runtime.cjs`；不要手改 `game/data/story.json`。
3. 流程或 UI 变化至少覆盖 `test_ui_flows.gd` 与真实 `Button.pressed` 测试；叙事变化覆盖 `test_story_flow.gd`。
4. 新角色/怪物资源必须有工程路径与加载测试，不把仅存在于生成目录的图片当作已接入。
5. 完成后运行 `_build/run_stage2_tests.ps1`；通过项、未验证项和范围外项分开记录。
