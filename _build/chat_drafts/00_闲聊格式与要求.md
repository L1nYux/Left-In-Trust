# 日常闲聊台词（重复游玩版）· 编写要求

本文件写给三名写手的机器可读要求；成品在 `docs/剧情/日常闲聊台词.md`，机器可读导出在 `docs/剧情/日常闲聊台词.json`。

## 1. 这是给谁在什么时候看的

剧情场景（正式的接单 / 核对 / 验收 / 战斗前中 / 成功 / 失败 / 结局小剧场）只在玩家**第一次**遇到该节点时完整播放。玩家重开、换任务、换人生阶段再来时，同样的节点不再重播场景，而是从「闲聊池」里抽一句轻快的日常台词顶上，让重复游玩不至于变成死板跳字。

所以写的是：**没有剧情推进任务的短句**。它不承担交代、不埋伏笔、不解释规则，只用来露出角色日常的样子，并且让玩家第二次、第三次看到时觉得「这两个人还挺好笑」。

## 2. 格式（必须严格照写，校验器按此解析）

每个台词块：

```
### 闲聊 · 角色 · context · 自言自语

<!-- chat
character: 角色
context: context 名
tags: 可选，逗号分隔
-->

- 角色：台词一。
- 角色：台词二。

### 闲聊 · 角色 → 同伴 · 同伴互动

<!-- chat
character: 角色
context: any
target: 同伴
tags: 可选
-->

- 角色：台词一。
```

规则：
- 标题行三种成分用全角「·」分隔；`→` 只在同伴互动块出现；结尾必须是「自言自语」或「同伴互动」。
- `<!-- chat` 与 `-->` 各占一行；头内只允许 `character` / `context` / `target` / `tags` 四个键，小写键名、半角冒号。
- 台词行一律 `- 角色：`（全角冒号），说话者必须等于块角色；一句一行，不要编号、不要引号、不要括号动作。
- 自言自语块 `context` 用下表 11 个枚举之一；同伴互动块 `context` 一律写 `any`，并用 `target` 指明对谁。
- UTF-8、LF 或 CRLF 均可，文件内不要写别的章节。

## 3. 每个角色至少写多少

| 类别 | 最低 | 建议 |
|---|---|---|
| 11 个 context 的自言自语 | 各 2 条 | 各 2–3 条 |
| 对另外两位同伴的互动 | 各 3 条 | 各 3–4 条 |

context 枚举（与正式事件的节点类型一一对应）：

| context | 玩家处在哪 | 可写的方向 |
|---|---|---|
| `open` | 刚进入一章 | 对重复的起点、熟悉的站台发牢骚或打气 |
| `brief` | 接到任务单 | 吐槽任务单、材料、打印口 |
| `check` | 正在核对材料 | 对反复出现的坑、截图、页脚发表意见 |
| `accept` | 验收通过 | 收工、入库、吃饭式的轻快收束 |
| `battle` | 战斗中 | 战斗口头禅、对纸页怪物的评价（不报数值） |
| `rest` | 休息站点 | 轮休、谁该睡、谁还在核对 |
| `shop` | 商店 | 买什么、值不值、砍价式吐槽 |
| `event` | 文本事件 | 对路遇小事的反应 |
| `boss` | Boss 前 | 紧张但轻快，不喊口号 |
| `ending` | 结局后 | 回望这一趟、说下次还来 |
| `idle` | 无事件的空闲 | 角色日常：吃、画、整理、发呆 |

## 4. 长度与语气

- 单句 ≤ 24 个汉字；单条 ≤ 2 句。
- 轻快、幽默、有生活气；可以拿「第三遍还是这张任务单」「这集我看过」这类重复游玩本身开玩笑。
- 允许自言自语，也允许对同伴互损，但要停在「清单太短 / 计划太厚 / 这步能省」这一级，不贬低人格、不攻击设定。
- 角色声线以 `docs/剧情/00_创作基准.md` §8 与 `剧情大纲.md` §五 为准：
  - GPT：计划、步骤、兜底、先拆步骤；小毛病是急着交付完整方案。
  - Claude：确认、最小改动、清单、边界；小毛病是把检查全揽下来。
  - DeepSeek：省步骤、省事、白饭、小鲸鱼；小毛病是太简洁漏掉别人需要的说明。
- 三人互相只按「对方这个角色」说话，不预知对方的私人暗线。

## 5. 禁区（校验器会拦或警告）

1. 不给知识、不给事实、不推进剧情、不点「我」的私人生活（不出现阿澄、阿栖、失败合照、纪念册、邀请、聚会等具体暗线物件；「邀请/附件」这类工作词偶尔出现可以，但不得指向暗线）。
2. 不使用括号动作、emoji、网络梗（yyds、绝绝子、破防、栓Q 等）、自称 AI、玩家吐槽、跨作品梗。
3. 不新增设定：不出现性别、外貌描写、公司名、学校名、具体人名。
4. 不报任何数值、牌名、规则（可以说「这步能省」，不能说「省 2 点算力」）。
5. 不重复正式剧情脚本里的原句；同一句不要在多个块里复用。
6. 不写战斗指令式台词（「使用 XX 卡」），只写人的反应。

## 6. 交付

写手只写自己那一个文件（`_build/chat_drafts/GPT.md` / `Claude_pool.md` / `DeepSeek.md`；Claude 文件名不能叫 `Claude.md`，会被工具当成说明文件加载），不改其他文件、不跑 git。

自检命令：

```
node _build/validate_chat.cjs --file _build/chat_drafts/<角色>.md --draft
```

0 错误后把共享任务标 completed，并把路径、块数、条数、校验摘要、偏差发回 Lead。
